# Known limitations

This is an OFFLINE EVIDENCE AND REVIEW COMPONENT DEMONSTRATION. Public source
access, including this review repository's history, was approved on 19 October 2026.

- The source, prompt, settings, candidates, advisory finding, reviewer identity,
  review decisions and logical timestamps are scripted synthetic inputs. No
  provider, live inference, model discovery or actual reviewer acceptance occurs.
- The predecessor receipt parameter hashes `fixtures/predecessor-anchor.json`,
  explicitly a synthetic demo anchor, not an authenticated production or release
  receipt. The source commit is real; this anchor grants no authority.
- The captured-output path does not run separate CoherenceLattice, Sophia or
  Atlas components. Named audit/posture packets are records, not execution proof.
  `STANDARD_PROFILE.finding_rules` is empty. The repair finding is injected via
  `register_platform_observed_transaction`, as in the source test. No AI discovered
  it and no semantic evaluator resolves it.
- Deterministic checks establish bounded evidence conditions, canonical/schema
  conformance, role/action predicates, linked states, package consistency and
  retained-byte identities. A hash or successful verification does not establish
  factual truth, completeness of real-world capture, model quality, compliance,
  control design adequacy or operating effectiveness.
- `APPROVE` is a scripted lifecycle event. Original findings remain separately
  visible, and the repair lineage retains `resolved_finding_ids=[]`. Business
  assessment and professional audit authority are not supplied by this harness.
  The source's 42-control snapshot is a proposed internal catalog, not validated
  standards mapping or observational business-control classification.
- Roles are logical enums/predicates in one process and writable local files.
  They are not separate OS principals or independent custody. A local owner able
  to rewrite all bytes and hashes is outside the integrity claim. Packages are
  hash-linked and unsigned, with no external signature, trusted timestamp or
  independently retained head. The tamper example changes one disposable copy.
- Standalone ZIP verification checks member content/topology and accepts trailing
  bytes after an otherwise intact ZIP. It is not an exact-container authenticity
  check. The live transaction snapshot separately binds the deterministic ZIP
  bytes and reports incomplete terminal evidence after trailing substitution.
  Both boundaries are exercised explicitly in the focused tests.
- No installer, startup qualification, native protected services, actual provider
  integration, full triadic cognition, retrosynthesis, P2P, PMR, MORALware or
  locally governed Sophia network is demonstrated. Those remain parts of the
  broader architecture/delivery plan, not erased product goals.
- The unchanged imported CLI also contains read-only loopback serving and other
  report surfaces because they are in its real import closure. The runner starts
  no listener or background service. No optional review-policy plugin is loaded.
  The optional `jsonschema` engine is not selected or installed; the default
  validator supports only the included schema vocabulary.
- Focused local positive/adverse tests cover this extraction only. They do not
  qualify the full product, other runtimes/platforms, accessibility, installation,
  crash recovery, hostile administrator scenarios or production scale.
- The new recovery example deliberately raises `TransitionInterrupted` after the
  first decision target through the existing fault-injection parameter. It covers
  one pre-seal transition, receipt/event binding, completion and a second no-op
  recovery. The engine receipt's `UNOBSERVED_PROCESS_INTERRUPTION` is its cause
  posture, not evidence of an actual OS crash, power loss or general recovery.
- Generated output remains local and ignored by Git. Keep any future real inputs
  under their actual access/retention policy. Approval to publish this reviewer
  source is not a formal release, hosted service, funding submission, deployment
  approval or qualification of the full product. The development repository
  remains private.
