# Offline inspection and reproducible verification

**Private planning concept; not submitted.** This smaller scope is not tied to a
particular funding program. Request amount, work estimate and costed plan are not
yet set and require the Founder's approval. No smaller dollar request is invented.

## Problem and prospective beneficiaries

Prospective users include small organizations and local software builders who
need to inspect AI-assisted work and retain a review history. A local, inspectable
evidence tool could support user control without a mandatory hosted service.
Demand and usefulness have not been established.

## One bounded milestone

Prepare a clearer local inspection and reproducibility package for the **existing
offline evidence tool**, with an approved costed scope before any request:

- Clarify the local report's evidence identities, scripted decisions, open findings
  and verification limits, so reviewers can follow a captured record and revision.
- Provide reproducible intact/modified/missing-evidence examples using the real
  directory and ZIP consumers, including the distinction between ZIP members and
  exact live-transaction ZIP-byte binding.
- Trace one existing interrupted-transition recovery path and document a bounded
  synthetic example with its observed outcome. Do not imply general crash recovery
  or success if that consumer has not actually been exercised.

Acceptance would be a small reviewed change, executable examples with explicit
expected positive/adverse outcomes and a readable local guide. Avoid a new engine,
governance framework or full-product commitment. A costed plan should identify
the precise changed consumer, paid contributor/supervision hours, infrastructure
needs and the subset that fits the approved request. No precise amount, staffing
commitment or schedule is proposed here.

## Evidence, boundaries and funding separation

The current [observed baseline](../../VALIDATION.md) is Windows Python 3.12.14:
eight focused tests passed, four directory/ZIP checks, linked repair and practitioner
export/reopen. Synthetic captured inputs, authored candidate, injected advisory and
scripted review are explicit; no model is called. Separate cognitive-component
execution, installed startup, actual human acceptance and P2P are not demonstrated.
See [known limitations](../../KNOWN_LIMITATIONS.md). This smaller concept does not
promise the full AI product, live-model integration or peer compute.
