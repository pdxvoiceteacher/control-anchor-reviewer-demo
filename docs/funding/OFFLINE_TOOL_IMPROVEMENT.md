## Problem and bounded milestone

Prospective users include small organizations and local software builders who
need to inspect AI-assisted work and retain a review history. Demand and
usefulness have not been established. The **existing offline evidence tool**
already includes intact/modified/missing-evidence examples using the actual
directory and ZIP consumers, plus one deliberately interrupted pre-seal decision
recovered through the existing engine. PR #1 supplied those bounded examples and
readable adverse outcomes. They are completed baseline work, not new deliverables
to fund again; they establish neither general crash recovery nor source truth.

A remaining smaller proposal could focus on observed inspection/usability gaps:

- Observe whether prospective reviewers can locate evidence identities, scripted
  decisions, open findings and preserved originals in the existing examples;
  record confusion and scope only the guide/navigation changes it supports.
- Improve reproducibility instructions for a declared supported setup using
  those same examples, retaining environment failures and the distinction between
  ZIP member checks and exact live-transaction ZIP-byte binding.

Acceptance would be documented reviewer observations, a small reviewed guide or
navigation change and a reproducibility handoff using the existing examples.
