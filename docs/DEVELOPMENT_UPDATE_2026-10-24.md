# Development update — 24 October 2026

## A shared core, with two intended interface paths

Control Anchor is pursuing an easier Windows UI for ordinary tasks and advanced
ComfyUI middleware for composing governed workflows. Both should reuse the same
portable task, control and evidence core. Nestable workflows are a design goal;
a graph edge or a child node does not create authority, additional budget or a
human approval. This is component development toward those paths, not a newly
qualified Windows product, SDK or working swarm.

## Resource capacity is not one pool of RAM

Host RAM, each GPU's VRAM, each volume's scratch storage and execution/CPU/I/O
slots retain their own units, physical identities and lifetimes. Adding disk or
another GPU does not make its capacity interchangeable with host RAM or a single
device's VRAM. Offload needs explicit backend support and incurs staging and I/O
costs. A timeout or cancelled request does not itself prove that residency or
scratch space has been released. Live placement, peak use and recovery still need
measurement; a planning estimate is not observed capacity.

## Reuse before rebuilding

The development research examines existing workflow, inference and orchestration
engines while keeping Control Anchor's authority and evidence responsibilities
explicit. A research reference or pseudocode is not an implemented integration.
Reuse must preserve applicable licenses and notices and review dependency,
modification, distribution and model-weight terms. A process boundary does not
automatically remove those obligations. This public update imports no engine code
or weights and changes no license grant.

## What still needs proof

Live ComfyUI execution, real model/GPU work, a complete candidate–challenge–correction
task or full swarm, durable nested authority, real human-approved export and
installed Windows equivalence remain unproven or inactive at this checkpoint.
The next useful comparison would carry the same bounded task through the actual
interfaces and core consumers, retaining failures, authority checks, effects and
reopened evidence. It requires its own execution and resource authority.

Older installation receipts keep their exact source and scope; these component
results do not qualify a newer installed product. The public badges test this
repository's synthetic reviewer demo and file/link integrity. A passing public
workflow does **not** verify the private product, ComfyUI, a GPU run or an installer.
